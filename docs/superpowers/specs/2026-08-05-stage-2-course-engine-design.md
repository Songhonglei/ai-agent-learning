# 阶段2：课程引擎与全局学习档案设计

> 状态：用户确认的设计，待实施计划
>
> 日期：2026-08-05

## 1. 目标与范围

阶段2将已验收的1-1纵向样板抽象为可复用课程引擎，并建立覆盖固定12课的版本化本地学习档案。阶段2只为已完成的1-1提供真实学习内容和记录；其他11课保留数据位置与介绍，不生成虚假进度或课程内容。

本阶段交付：

- 通用课程 Schema、步骤渲染协议和全局 `LearningProfile`；
- 从阶段1五字段1-1记录迁移到全局档案；
- 版本化 Schema、受控迁移、JSON 导入/导出与合并预览；
- 错题、收藏、复习队列、三题前测和三题后测；
- 1-1接入上述通用能力、学习档案界面与全量验证。

本阶段不交付：其余11课的课稿或互动、真实模型服务、网络教学依赖、前端密钥、部署或远程写入。

## 2. 全局学习档案

使用单个版本化的本地档案 `LearningProfile`。它的版本从 `schemaVersion: 1` 开始，包含：

- `theme`、`currentLessonId`、`currentStepId`；
- 以12个固定课程ID为索引的课内进度与完成状态；
- 错题记录、收藏的稳定内容ID和复习队列；
- 前测、后测的答案、完成时间与结果；
- `updatedAt`，仅用于导入预览、合并解释与最近访问展示，不作为并发事务承诺。

所有存储读写都使用白名单投影；未知字段不进入运行时档案。空档案、损坏档案、存储拒绝、未知未来版本和迁移失败必须有不污染旧数据的可恢复状态。

阶段1遗留键 `ai-agent-learning:lesson-1-1:progress` 是唯一旧输入：首次全局加载时将其五个字段迁移到 `courses['1-1']`，保留主题、当前课和当前步骤。只有成功写入全局档案后才清理旧键；失败时保留旧键并提示可重试。迁移是幂等的。

## 3. 课程引擎与配置

课程继续由 TypeScript 配置驱动，固定步骤协议：`scene`、`dialogue`、`experiment`、`quiz`、`summary`、`free-question`。引擎只负责按配置渲染、推进、恢复和写入全局档案；互动、来源和测验组件保持独立。

1-1先接入通用引擎。其余11课只保留课程ID、名称、简介、模块和推荐路径，不配置可学习步骤、测验或实验。

## 4. 学习记录规则

- **错题：** 错答自动记录题目ID、课程ID、错因和来源ID。答对不自动删除；用户可在复习页标记“已掌握”。
- **收藏：** 收藏概念、来源卡和题目等稳定内容ID，不复制长正文。
- **复习：** 默认队列为未掌握错题与主动收藏，可按课程和类型筛选；不使用推送、提醒或复杂算法。
- **前/后测：** 各3题，后测与前测等价但不复用题干。仅展示前后结果，不用于用户标签或个性化分层。阶段2先让1-1使用这套通用数据和组件。

## 5. 导入、导出与多标签规则

导出为一个仅含学习档案、不含课程正文的 JSON 文件。导入流程固定为：选择文件 → 格式/版本/字段校验 → 合并预览 → 用户明确确认 → 写入结果。取消、校验失败或未知未来版本不得修改当前档案。

本地与导入档案合并规则：同一课程取完成度更高、答案更完整的一方；错题与收藏按稳定ID去重；前后测与当前步骤选择更新时间较晚的有效记录；合并结果与冲突取舍必须在预览中可读。

档案的 `storage` 事件同步全部标签。新值经校验后成为权威状态；损坏事件值不覆盖当前有效状态。真正同时从同一旧值写入时采用浏览器最后写入者胜出，所有标签最终收敛；本阶段不引入跨进程事务或额外并发版本字段。

## 6. 界面与可访问性

保留当前地图和课程页面，新增“学习档案”入口，至少包含：进度概览、错题、收藏、复习、前后测、备份/恢复。导入预览清楚显示可导入项、合并取舍、拒绝原因和确认动作。

沿用冻结的色彩、1200px桌面容器、310px导师列、移动断点、可见焦点与减弱动态效果。关键操作无需拖拽；所有状态不能只靠颜色表达。

## 7. 验收标准

- 旧1-1记录可无损、幂等迁移；迁移失败不会丢失旧记录。
- 版本升级、损坏JSON、未知未来版本、存储错误均有可恢复流程。
- 导出JSON可校验并导回；预览后合并符合固定规则，取消不写入。
- 1-1的错题、收藏、复习和前/后测形成完整本地闭环。
- 前测与后测均为3题且不复用题干；未开放课程无假进度。
- 多标签同步与导入后的收敛经过组件和浏览器级验证。
- 单元、组件、端到端、构建、375–1440px、键盘与关键对比度检查均通过。
- 没有模型调用、网络教学依赖、前端密钥、发布或远程写入。
