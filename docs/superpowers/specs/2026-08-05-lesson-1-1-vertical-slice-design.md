# 1-1《Agent的记忆有边界》纵向样板设计

> **状态：** 用户已确认，待转实施计划。
>
> **范围：** v0.1 的首个可运行样板；只覆盖学习地图与 1-1 完整学习链路。

## 1. 目标

在仓库根目录新建 React + Vite + TypeScript 应用。新用户能从学习地图进入 1-1，完成本地的上下文构建器和情境测验，查看来源依据，刷新后恢复本课进度，并在没有模型服务时使用 FAQ。

成功不是“做出通用课程平台”，而是以一个可测试、可访问、可追溯的真实课例验证课程播放器的最小边界。

## 2. 已冻结范围

### 包含

- 6 节点学习地图；其他 11 课显示课程介绍和推荐路径，1-1 可直接进入。
- 1-1 链路：情境导入 → 对话讲解 → 上下文构建器 → 情境测验及三级解析 → 来源依据 → 自由提问入口与 FAQ。
- Light/Dark 主题、桌面和移动端关键流程、加载/空/错误状态、键盘可达。
- 只保存 1-1 的本地进度：主题、当前步骤、已完成步骤、构建器选择和测验答案；刷新恢复。
- 图 2-1 的授权语义重绘与完整文字替代。

### 明确不包含

- 真实模型调用、网络请求、前端密钥、发布或远程写入。
- 其余 11 课的课稿、互动或题库。
- 全局错题、收藏、复习、前测、后测、Schema 迁移和学习进度导入/导出；这些都属于阶段 2。

## 3. 信息与教学设计

### 3.1 可讲事实

只使用 `reference/source-audit/lesson-1-1-source-pack.md` 已确认的事实：

1. Agent 在每个决策点只能基于当前上下文窗口中的信息行动。
2. 上下文包括系统规则、用户请求、既往助手回复、工具调用与结果等，而不只是聊天记录。
3. 任务所需的代码、流程或环境信息缺失时，Agent 可能给出表面合理、却不符合当前任务约束的回答。
4. 课程行动结论是先检查“它此刻看得到什么”，而不是只堆叠泛化指令。

`page-052` 的缓存内容只作为生产级扩展提示，不进入互动判定或测验；不引用具体模型窗口、价格或版本。

### 3.2 对话与互动

课程使用预设脚本，不由模型临场生成。红叔先以“交给新同事修复一个问题”为情境解释：信息不全时，聪明也不能替代背景。

上下文构建器使用一个确定性场景“修复支付页异常”。学习者在可选信息块中选择：

- 代码与报错上下文；
- 团队流程与分支约束；
- 测试/运行环境；
- 与任务无关的信息。

前三项构成该场景的最低信息需求。缺任一项时，反馈必须说明缺什么、可能造成什么约束错误；三项齐全时，只说明“具备按约束继续分析的必要背景”，不得承诺任务一定完成。无关信息不能替代必需信息。

### 3.3 测验、来源与 FAQ

- 情境测验只考“是否缺少关键背景”“哪些信息应进入当前轮上下文”“信息充分与不足为何会改变表现”。每题均有即时对错、理由、原书依据三级反馈；答错不阻断。
- 来源依据页显示 PDF 34/35/52、来源 ID、可讲结论、边界和图示处理说明。
- “自由提问”是入口占位，不发送请求；FAQ 只给出本课审核答案，并说明真实模型服务尚未启用。

## 4. 应用结构

```text
src/
  app/                 # 路由、主题和应用壳
  content/             # 学习地图、1-1脚本、题目、FAQ和来源引用
  features/
    learning-map/      # 6节点地图与课程介绍
    lesson-player/     # 步骤推进和进度恢复
    context-builder/   # 确定性选择与反馈
    quiz/              # 题目与三级解析
    source-evidence/   # 来源依据与图示文字替代
    ask-hongshu/       # FAQ和无服务占位
  shared/
    storage/           # 仅1-1的安全本地读写
    ui/                # 可访问基础组件
    types/             # 课程、步骤与进度类型
```

应用使用浏览器路由：`/` 为学习地图，`/lesson/1-1` 为课程页。课程内容由 TypeScript 配置驱动，至少支持 `scene`、`dialogue`、`experiment`、`quiz`、`summary`、`free-question` 六种步骤。阶段 1 的配置只实现 1-1，不冒充通用 12 课引擎。

进度存储接口只有 `loadLessonProgress()`、`saveLessonProgress()` 与 `clearLessonProgress()`；读取损坏数据、无痕模式写入失败或存储不可用时回退到内存状态并给出可理解提示。不得在阶段 1 引入版本迁移、导入或导出协议。

## 5. 视觉、状态与无障碍

- 采用 `03-视觉设计规范.md` 的颜色 Token、字体、布局和 `visuals/hongshu-avatar.svg`。
- 以图 2-1 的语义重绘为一张 CSS/SVG 关系图：系统提示、用户消息、助手回复、工具调用/结果、当前生成位置和有限窗口均以文字可见；图下提供完整文字替代。
- 宽屏遵循地图与课程三栏布局；窄屏折叠为单列，所有关键操作不依赖拖拽。
- 所有交互有键盘操作、可见焦点、文本标签与状态说明；主题切换保留对比度。
- 为课程加载、无可恢复进度、存储写入失败、未知路由和 FAQ 空结果提供明确、可恢复的页面状态。

## 6. 测试与验收

### 自动化测试

- Vitest：步骤推进、上下文构建器判定、测验反馈、本地进度读写与损坏回退。
- Testing Library：学习地图到 1-1 的进入、主题切换、键盘完成构建器和 FAQ 占位。
- Playwright：桌面和移动端完成“首页 → 1-1 → 构建器 → 测验 → 来源 → 刷新恢复”的关键路径。

### 人工验收

1. 新用户可从首页进入 1-1，不被软锁定阻断。
2. 构建器的充分与缺失反馈分别准确、克制且可追溯。
3. 测验、来源、FAQ 均没有模型调用路径。
4. 图示和全部语义不依赖颜色或图标；Light/Dark 与移动端可读。
5. 刷新可恢复本课状态；存储失败不会阻断课程。
