# 开源项目验证经验

## 2026-10-21：将练习与结果测量分开

现有课内测验选择即反馈，适合练习；全课程前后测另设题卷、保存草稿、提交后反馈，并将既有学习记录标为补测。按课与主题覆盖测试、前后题干不复用检查、提交前无解析的浏览器检查已通过。不能仅靠前后分差证明课程因果效果。

## 2026-10-21：连续作答需要有序保存

原云端updateProfile可并发写完整档案，旧请求可能晚返回并覆盖新状态。修复为按顺序写入，仅在返回对应当前草稿时应用响应，期间提示等待。延迟保存桩测试确认第二笔排队、已选答案保持、最后完成后清除等待提示。本轮未用真实账号或数据库验证。

## 2026-10-21：对测评档案明确版本边界

v1读取投影为v2，旧局部成绩不冒充全课程基线；新版API拒绝v1写入防止降级覆盖。旧档案恢复和两种新测评草稿/结果JSON往返均有验证；发布前必须同时检查客户端与API的版本兼容。


## 2026-10-21：目录移动与预览服务路径

普通独立Git根目录可原位rename；先核对无目标冲突及无linked worktree。迁移前后HEAD、Git状态和270个已跟踪文件散列一致。Vite预览进程保存旧绝对路径，因此从新目录在相同127.0.0.1:4182重启；首页、测评深链与JS/CSS实际200。OpenViking注册工作区及策略project字段同步修改，保留code/scope，真实MCP resolve新路径仍返回原项目标识。只改目录不需要重跑课程全量测试。


## 2026-10-21：从Vercel请求日志定位主备失败

Code配置保存并新建预览后，真实UI问答仍失败。Vercel日志列表将3条warning聚合成一行，需打开请求行并等待日志详情，再核对primary HTTP_403、fallback HTTP_401及External APIs中的实际Code路径；不能把仅列表末条AI_UPSTREAM_ERROR当作没有主备状态。官方401可能对应认证或能力权限，不能仅凭状态断言无额度、Key错误或编程用途限制。控制台生效Key元数据也不能证明Vercel Secret填写一致；由用户核对密钥并保存后再创建新部署，不反复调用相同失败凭据。


## 2026-10-21：分别验收Preview与Production密钥及实际调用链

用户更新两环境密钥后，先在Preview验证跨课回答/引用/超范围降级，再检查项目原有自动生产域名分配Disabled，用Production变量创建暂存；暂存问答及前测草稿刷新通过后才手动promote同一构建。正式域名ID与alias completed、真实UI回答、资源及390px布局再核对。HTTP200也可能是安全拒答，或主供应商在HTTP200载荷中报错后才切备用，需结合回答引用及External APIs/主403日志确认，不把HTTP200泛化为回答质量通过。相关问法的一次安全降级作为待优化项保留。


## 2026-10-21：无引用不等于课程没有覆盖

旧实现把无引用一律改写为资料未覆盖；初次只强化提示，真实4-2仍漏引。最终使用JSON状态/正文/引用并兼容旧格式，缺引用/坏结构各自可重试，明确拒答不调用备用；所有来源仍校验本课表格白名单，正文已有合法行内引用可回收，不自动配号。59项测试与本地/真实浏览器验证完成，原问法在正式站带正确来源回答。

生产发布需每次读取Auto-assign真实值：前次promote后的值不能推定仍Disabled。本轮create production即自动成为current，promote409明确已是当前版本，停止重试；读取网页Enabled后恢复已知原始false，网页确认手动发布。按实际过程记录，不把计划的暂存流程写成已执行结果。
