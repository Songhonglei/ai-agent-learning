## 用途与边界

本包服务于课程 **0-2 三句话理解 Agent**。学习者完成本课后，应能用一句公式和一个日常任务说明 Agent 的三个组成部分：LLM（大脑）、上下文（眼睛）和工具（手脚）。

本包不进入强化学习形式化、模型训练细节或具体厂商功能。第 5、7、9 章仍属于未来的技术人员专用章节，不进入当前正式课程映射。

## 课内事实链

1. **LLM（大脑）**：在当前信息基础上理解请求、思考并决定下一步。
2. **上下文（眼睛）**：是 Agent 在当前决策点能看到的任务信息，例如环境信息、用户记忆、领域知识、自身状态和任务进展；不只是用户刚输入的一句话。
3. **工具（手脚）**：是 Agent 可以使用的手段，使它能查询、操作或与外部世界交互；实际使用仍受权限和产品边界约束。
4. 三者缺一不可：只有大脑但看不到任务信息，无法按当前条件判断；看到了信息但没有可用手段，不能把决定落实为行动；工具调用后若看不到结果，也无法可靠决定下一步。

## 证据表（替代原书实验视觉）

| 对照条件 | 可验证结果 | 本课解释 |
| --- | --- | --- |
| 完整基线 | 正常工作 | Agent 需要完整的运行所需信息与手段。 |
| 无工具定义 | 无法调用工具 | Agent 要先知道有哪些工具及如何使用。 |
| 无推理过程 | 决策不连贯 | 行动需要连贯的决策过程。 |
| 无历史记录 | 重复操作 | 过去发生过什么会影响当前下一步。 |
| 无工具结果 | 盲目循环 | 行动结果是决定下一步的重要信息。 |

## 互动与测验依据

**三要素拆解器：** 给出一个已获授权的通用办公任务，例如“根据会议规则安排候选时间并发出待确认的邀请”。学习者把“理解优先级并决定下一步”放入 LLM，把“参会人、日历、规则和已发生结果”放入上下文，把“查询日历、生成并发送待确认邀请”放入工具。

**填空与匹配测验：** 题干只能考察：

- 大脑 / 眼睛 / 手脚分别对应 LLM / 上下文 / 工具；
- 给定任务信息或能力，应归到哪一个组成部分；
- 缺少工具定义、历史记录或工具结果时，为什么任务推进会受影响。

不得把“上下文越长越好”、任何模型版本、工具权限或产品功能范围写成无条件结论。
