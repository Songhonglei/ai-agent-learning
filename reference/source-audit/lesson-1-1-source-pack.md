## 用途与边界

本包服务于纵向样板课 **1-1 Agent的记忆有边界**。对应课程目标为：理解上下文窗口，并能在情境中判断 Agent 是否会因关键信息缺失或容量限制而“忘事”。

本包只陈述 `reference/原始文档.pdf` 第2章可追溯的结论；不把厂商上下文长度、缓存价格或模型版本当作稳定课程事实。第5、7、9章仍属于未来技术人员版，不进入本课。

## 课内事实链

1. Agent 每次作答只能基于本轮上下文窗口中的信息。
2. 上下文由规则、用户请求、既往回复、工具调用及结果等组成；它不是只有聊天记录。
3. 当任务所需的代码、流程、环境或此前结果没有被放入当前窗口时，Agent 可能给出看似合理、却不符合当前任务约束的回答。
4. 因此，本课的行动结论是：在让 Agent 执行任务前，先检查“它此刻看得到什么”，而非只增加一条泛化指令。

## 视觉与可访问性要求

- 只重绘 `figure-2-1` 的关系，不直接复用原图。
- 重绘图必须标出：系统提示、用户消息、助手回复、工具调用/结果、当前生成位置、有限窗口。
- 图下必须提供与审计决定一致的文字替代：上下文窗口由上述信息组成；关键信息缺失或窗口不足会造成“忘记”或判断失真。
- 不用颜色、图标或箭头作为唯一信息载体。

## 互动与测验依据

**上下文构建器：** 给出同一任务的两种输入：一种缺少流程或工具结果，另一种补齐必要信息。学习者判断 Agent 在当前轮是否具备完成任务的条件，并指出缺失项。

**情境测验：** 题干只能考察以下可追溯判断：

- 缺少任务所需背景或工具结果，是否可能造成错误判断；
- 哪类信息应进入本轮上下文；
- 同一模型在信息充分与信息不足时为何会有不同表现。

不得把“上下文越长越好”、具体模型窗口大小、缓存计费或任何厂商行为写成无条件结论。
