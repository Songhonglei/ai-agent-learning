# 0-1《你已经在用 Agent 了》来源包

## 用途与边界

本包服务于课程 **0-1 你已经在用 Agent 了**。学习者完成本课后，应能在日常场景中判断：一个系统是在单次生成答案，还是会围绕目标读取信息、调用工具、根据结果继续推进任务。

本包只使用 `reference/原始文档.pdf` 中已经审核的导论与第 1 章事实。产品名称和功能示例仅用于说明原书写作时列举的形态；本课不把任何厂商、版本或当前产品能力当作稳定课程事实，也不承诺真实世界操作会在未获用户授权时执行。

## 课内事实链

1. Agent 的日常形态可以是研究、跨系统办事、辅助完成复杂工作等；外观不必是单独的“Agent 产品”。
2. 与单次聊天回答相比，Agent 会围绕目标规划步骤，读取任务所需信息，调用可用工具，并根据结果继续调整。
3. 因而判断一个场景是不是 Agent，不能只看它有没有聊天窗口或产品名称，而要看该任务里是否出现了“目标 → 获取信息 / 行动 → 结果反馈 → 下一步”的推进过程。
4. 工具能力应在用户授权与系统边界内使用；本课不把“能执行动作”误解为“可以不经确认地替用户做任何事”。

## 视觉与可访问性要求

- 本课不直接复用原书中的厂商产品截图或标识。
- 用统一网页风格重绘一个通用任务循环：目标 → 读取相关信息 → 调用工具行动 → 查看结果 → 调整下一步。
- 图下必须提供文字替代：Agent 不是只回答一次；它会围绕目标读取信息、使用工具、查看结果并继续推进。 
- 不用颜色、图标或箭头作为唯一信息载体。

## 互动与测验依据

**身边的 Agent 识别器：** 为每个场景分别列出系统能否读取任务信息、是否能调用工具、是否会根据工具结果继续推进。学习者选择“仅聊天回答”“具备 Agent 工作方式”或“信息不足，不能断定”。

**情境测验：** 题干只能考察以下可追溯判断：

- 单次生成文字与围绕目标推进多步任务的区别；
- 工具结果和持续调整为什么属于 Agent 工作方式；
- 只给出产品名或聊天界面时，为什么不能据此断定它一定是 Agent。

不得考察某一家产品今天能否订票、发邮件或操作浏览器；不得把没有外部行动的聊天系统一概贬低为“没用”。
